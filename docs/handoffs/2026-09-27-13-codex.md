## 2. Implemented behavior

- Shared text is checked before persistence for password assignments,
  recovered-password assignments, candidate-list labels, wallet-byte labels,
  and user-configured sensitive paths.
- Artifact registration accepts only bounded metadata: ID, run ID, label, kind,
  size, and lowercase SHA-256. It cannot accept file paths or source bytes.
- Handoff IDs are restricted to bounded path-safe identifiers.
- Handoff content is UTF-8, non-empty, limited to 64 KiB, checked for sensitive
  content, flushed to stable storage, and SHA-256 hashed.
- Publication uses a same-directory temporary file and an atomic hard-link
  create that cannot replace an existing handoff path.
- The handoff row, publication event, and file publication are coordinated with
  one immediate SQLite transaction. Failures roll back and clean created files.
- Reusing either a handoff ID or path raises `ConflictError` without changing
  the existing file or database row.

This is an operational privacy control, not a security boundary against a
malicious local process with filesystem or database write access.
