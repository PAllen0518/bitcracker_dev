## 2. What was done this session

Paul authorized proceeding from checkpoint `2026-09-27-20-codex` (RED). I took
the builder role and drove the scoped GREEN increment that makes the three
frozen RED tests pass without changing any test assertion. No new dependency
was added.

`Workspace.claim_task` now enforces the acknowledgment gate: a task that is the
target of any handoff with `acknowledged_at IS NULL` cannot be claimed and
raises `ConflictError`. Tasks with no handoff are unaffected.

`Workspace.acknowledge_handoff` is implemented. It matches the exact handoff id,
recipient, and SHA-256 in one query; a nonexistent handoff, wrong recipient, or
wrong hash all fail closed as `ConflictError`. On a match it stamps
`acknowledged_at`, records one `handoff_acknowledged` event, and returns the
acknowledgment record.

`Workspace.publish_handoff` now accepts `supersedes_handoff_id`, validates it as
an identifier, and stores it. The predecessor file, row, and event are left
unchanged; publication still appends exactly one event.

The schema gains one column, `handoffs.supersedes_handoff_id`, a self-reference
to `handoffs(id)` with `ON DELETE RESTRICT`. This is a schema edit rather than a
migration: the coordination database is greenfield and untracked, so no
released schema exists to migrate.

`tools.agent_workspace_mcp.main` implements the bounded newline-delimited
JSON-RPC stdio loop: it binds the workspace named by
`BITCRACKER_AGENT_WORKSPACE`, answers `initialize`, `tools/list`, and
`tools/call`, treats id-less messages as notifications with no response, maps
`McpRequestError`/`WorkspaceError` to JSON-RPC error objects, and exits 0 at
EOF. The tool catalog is unchanged (eight bounded tools).
